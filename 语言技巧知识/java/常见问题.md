## JVM原理相关问题

### 问题1: JVM内存结构

**问题：** 请描述JVM的内存结构，并说明各部分的作用。

**参考答案：**
```java
/**
 * JVM内存结构主要分为以下几个部分：
 * 
 * 1. 程序计数器（Program Counter Register）
 *    - 线程私有，记录当前线程执行的字节码行号
 *    - 唯一不会出现OutOfMemoryError的区域
 * 
 * 2. Java虚拟机栈（Java Virtual Machine Stacks）
 *    - 线程私有，存储栈帧（方法调用的局部变量、操作数栈等）
 *    - 可能出现StackOverflowError和OutOfMemoryError
 * 
 * 3. 本地方法栈（Native Method Stack）
 *    - 线程私有，为Native方法服务
 * 
 * 4. Java堆（Java Heap）
 *    - 线程共享，存放对象实例和数组
 *    - 垃圾回收的主要区域
 *    - 可能出现OutOfMemoryError
 * 
 * 5. 方法区（Method Area）
 *    - 线程共享，存储类信息、常量、静态变量等
 *    - JDK8之前称为"永久代"，JDK8+称为"元空间"
 *    - 可能出现OutOfMemoryError
 */

// 示例：查看JVM内存使用
public class MemoryDemo {
    public static void main(String[] args) {
        Runtime runtime = Runtime.getRuntime();
        
        System.out.println("最大内存: " + runtime.maxMemory() / 1024 / 1024 + "MB");
        System.out.println("总内存: " + runtime.totalMemory() / 1024 / 1024 + "MB");
        System.out.println("空闲内存: " + runtime.freeMemory() / 1024 / 1024 + "MB");
        
        // 手动触发GC（仅用于演示，生产环境慎用）
        System.gc();
    }
}
```

### 问题2: 垃圾回收机制

**问题：** 请解释Java的垃圾回收机制，并说明常见的垃圾回收器。

**参考答案：**
```java
/**
 * Java垃圾回收机制：
 * 
 * 1. 引用计数法（已淘汰）
 *    - 每个对象维护一个引用计数器
 *    - 无法解决循环引用问题
 * 
 * 2. 可达性分析算法（当前使用）
 *    - 从GC Roots对象开始，标记所有可达对象
 *    - 不可达对象被视为垃圾
 *    - GC Roots包括：虚拟机栈中引用的对象、方法区中静态属性引用的对象等
 * 
 * 常见的垃圾回收器：
 * 
 * 1. Serial收集器
 *    - 单线程，新生代使用复制算法
 *    - 适用于客户端应用
 * 
 * 2. Parallel收集器（吞吐量优先）
 *    - 多线程，新生代使用复制算法
 *    - 适用于后台计算应用
 * 
 * 3. CMS收集器（低延迟）
 *    - 并发标记清除，减少停顿时间
 *    - 适用于Web应用
 * 
 * 4. G1收集器（JDK9+默认）
 *    - 分区收集，可预测的停顿时间
 *    - 适用于大内存应用
 * 
 * 5. ZGC收集器（JDK11+）
 *    - 低延迟，支持TB级堆内存
 *    - 停顿时间不超过10ms
 */

// 示例：观察GC行为
public class GCDemo {
    public static void main(String[] args) {
        // 设置JVM参数观察GC
        // -XX:+PrintGCDetails -XX:+UseG1GC
        
        List<byte[]> list = new ArrayList<>();
        
        for (int i = 0; i < 1000; i++) {
            // 创建1MB的数组，观察GC行为
            byte[] data = new byte[1024 * 1024];
            list.add(data);
            
            if (i % 100 == 0) {
                System.out.println("已分配: " + (i + 1) + "MB");
            }
        }
    }
}
```

## 并发编程相关问题

### 问题3: synchronized和ReentrantLock的区别

**问题：** 请比较synchronized和ReentrantLock的异同。

**参考答案：**
```java
import java.util.concurrent.locks.ReentrantLock;

/**
 * synchronized vs ReentrantLock：
 * 
 * 相同点：
 * 1. 都是可重入锁
 * 2. 都保证线程安全
 * 
 * 不同点：
 * 1. 实现机制：
 *    - synchronized是JVM层面的关键字
 *    - ReentrantLock是JDK提供的API
 * 
 * 2. 灵活性：
 *    - synchronized使用简单，自动释放锁
 *    - ReentrantLock功能更丰富，支持公平锁、可中断、超时等
 * 
 * 3. 性能：
 *    - JDK6之后synchronized性能大幅提升
 *    - 高竞争情况下ReentrantLock性能更好
 * 
 * 4. 锁的获取：
 *    - synchronized无法中断等待的线程
 *    - ReentrantLock支持尝试获取锁和中断等待
 */

public class LockComparison {
    
    // synchronized实现
    private int synchronizedCounter = 0;
    
    public synchronized void incrementSync() {
        synchronizedCounter++;
    }
    
    // ReentrantLock实现
    private int reentrantCounter = 0;
    private final ReentrantLock lock = new ReentrantLock();
    
    public void incrementReentrant() {
        lock.lock();
        try {
            reentrantCounter++;
        } finally {
            lock.unlock();
        }
    }
    
    // 尝试获取锁（ReentrantLock特有）
    public boolean tryIncrement() {
        if (lock.tryLock()) {
            try {
                reentrantCounter++;
                return true;
            } finally {
                lock.unlock();
            }
        }
        return false;
    }
    
    // 可中断锁（ReentrantLock特有）
    public void interruptibleIncrement() throws InterruptedException {
        lock.lockInterruptibly();
        try {
            reentrantCounter++;
        } finally {
            lock.unlock();
        }
    }
}
```

### 问题4: volatile关键字的作用

**问题：** 请解释volatile关键字的作用和原理。

**参考答案：**
```java
/**
 * volatile关键字的作用：
 * 
 * 1. 保证可见性
 *    - 当一个线程修改volatile变量时，新值会立即刷新到主内存
 *    - 其他线程读取时会从主内存重新加载
 * 
 * 2. 禁止指令重排序
 *    - 通过内存屏障防止编译器和处理器重排序
 *    - 保证happens-before关系
 * 
 * 但volatile不保证原子性：
 * - 对于复合操作（如i++），仍需使用synchronized或原子类
 */

public class VolatileDemo {
    
    // volatile保证可见性
    private volatile boolean flag = false;
    
    public void writer() {
        flag = true; // 写操作，保证对其他线程可见
    }
    
    public void reader() {
        while (!flag) {
            // 空循环，等待flag变为true
        }
        System.out.println("Flag is true");
    }
    
    // volatile不保证原子性的示例
    private volatile int count = 0;
    
    public void unsafeIncrement() {
        count++; // 这不是原子操作，可能出问题
    }
    
    // 正确的方式：使用原子类
    private java.util.concurrent.atomic.AtomicInteger atomicCount = 
        new java.util.concurrent.atomic.AtomicInteger(0);
    
    public void safeIncrement() {
        atomicCount.incrementAndGet(); // 原子操作
    }
}

// 单例模式中的volatile应用（双重检查锁定）
class Singleton {
    private static volatile Singleton instance;
    
    private Singleton() {}
    
    public static Singleton getInstance() {
        if (instance == null) { // 第一次检查
            synchronized (Singleton.class) {
                if (instance == null) { // 第二次检查
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

### 问题5: HashMap的工作原理

**问题：** 请详细说明HashMap的工作原理，包括put和get过程。

**参考答案：**
```java
import java.util.HashMap;
import java.util.Map;

/**
 * HashMap工作原理：
 * 
 * 1. 数据结构：数组 + 链表/红黑树（JDK8+）
 * 2. 默认容量：16，负载因子：0.75
 * 3. 扩容机制：当元素数量超过容量*负载因子时，扩容为2倍
 * 
 * put过程：
 * 1. 计算key的hash值
 * 2. 通过hash & (n-1)计算数组下标
 * 3. 如果该位置为空，直接插入
 * 4. 如果发生哈希冲突：
 *    - 如果是链表，遍历链表
 *    - 如果是红黑树，遍历树
 * 5. 如果找到相同key，更新value
 * 6. 如果没找到，插入到链表/树中
 * 7. 如果链表长度超过8，转换为红黑树
 * 8. 如果元素数量超过阈值，进行扩容
 * 
 * get过程：
 * 1. 计算key的hash值
 * 2. 通过hash & (n-1)计算数组下标
 * 3. 遍历链表/树，找到对应key的节点
 * 4. 返回value
 */

public class HashMapAnalysis {
    
    public static void main(String[] args) {
        Map<String, Integer> map = new HashMap<>();
        
        // put操作分析
        map.put("key1", 1);
        map.put("key2", 2);
        map.put("key3", 3);
        
        // 哈希冲突示例
        // 如果两个key的hash值相同，会发生哈希冲突
        map.put("Aa", 100);
        map.put("BB", 200); // "Aa"和"BB"的hashCode相同
        
        // get操作分析
        Integer value = map.get("key1");
        System.out.println("key1的值: " + value);
        
        // 遍历HashMap
        for (Map.Entry<String, Integer> entry : map.entrySet()) {
            System.out.println(entry.getKey() + ": " + entry.getValue());
        }
    }
    
    // 自定义对象作为key的注意事项
    static class Person {
        String
