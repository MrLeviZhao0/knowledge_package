## 常见面试问题及回答策略

### 基础概念类问题

**问题1：JNI的主要作用是什么？在什么场景下需要使用JNI？**

**回答策略：**
- **性能优化**：执行计算密集型任务，如图像处理、加密解密
- **代码复用**：复用现有的C/C++库，如OpenCV、FFmpeg
- **系统访问**：访问操作系统底层功能，如硬件控制、系统调用
- **硬件控制**：直接控制硬件设备，如传感器、摄像头

**问题2：JNI数据类型映射的规则是什么？**

**回答策略：**
- **基本类型映射**：boolean→jboolean, int→jint, long→jlong等
- **引用类型映射**：Object→jobject, String→jstring, Class→jclass
- **数组类型映射**：int[]→jintArray, Object[]→jobjectArray
- **特殊规则**：注意long在JNI中是64位，在C中可能是32位

### 技术实现类问题

**问题3：JNIEnv是什么？它的主要作用是什么？**

**回答策略：**
- **定义**：JNIEnv是JNI接口的核心结构体，包含指向方法表的指针
- **作用**：提供访问Java虚拟机的所有功能方法
- **线程关联**：每个线程有独立的JNIEnv，不能跨线程使用
- **方法分类**：包括对象操作、字符串处理、数组操作、方法调用等

**问题4：JNI方法签名是如何工作的？请举例说明。**

**回答策略：**
- **签名规则**：使用特定字符表示类型，如I表示int，Ljava/lang/String;表示String
- **方法格式**：(参数类型)返回类型
- **示例1**：`String method(int, String)` → `(ILjava/lang/String;)Ljava/lang/String;`
- **示例2**：`void process(byte[], int)` → `([BI)V`
- **工具使用**：可以使用javap -s查看方法签名

### 性能优化类问题

**问题5：如何优化JNI调用的性能？**

**回答策略：**
- **减少调用次数**：批量处理数据，避免频繁的JNI调用
- **缓存ID**：缓存字段ID和方法ID，避免重复查找
- **使用直接缓冲区**：使用NIO的DirectBuffer避免数据拷贝
- **本地化处理**：在Native层完成复杂计算，减少数据传递

**问题6：JNI调用有哪些性能开销？**

**回答策略：**
- **方法调用开销**：JNI方法调用比Java方法调用慢5-10倍
- **数据转换开销**：数据类型转换需要额外的时间和内存
- **边界检查开销**：JNI层需要进行参数和边界检查
- **异常处理开销**：异常处理比正常流程更耗时

## 实战案例分析

### 案例1：JNI内存泄漏问题

**场景描述：**
应用长时间运行后出现内存泄漏，Native层内存持续增长

**分析思路：**
1. **检查全局引用**：确认全局引用是否及时释放
2. **检查局部引用**：确认在循环中是否创建过多局部引用
3. **检查直接内存**：确认DirectBuffer是否正确释放
4. **检查Native内存**：确认Native层是否有内存泄漏

**解决方案：**
```c
// 问题代码：局部引用未及时释放
for (int i = 0; i < 10000; i++) {
    jstring str = (*env)->NewStringUTF(env, "test");
    // 使用str但没有释放
    // 应该添加：(*env)->DeleteLocalRef(env, str);
}

// 修复方案：及时释放局部引用
for (int i = 0; i < 10000; i++) {
    jstring str = (*env)->NewStringUTF(env, "test");
    // 使用str
    process_string(env, str);
    // 及时释放
    (*env)->DeleteLocalRef(env, str);
}
```

**优化效果：**
- 内存使用稳定，不再持续增长
- 应用长时间运行无内存问题
- GC压力显著降低

### 案例2：JNI性能优化

**场景描述：**
图像处理应用JNI调用频繁，性能瓶颈明显

**分析思路：**
1. **性能分析**：使用Systrace分析JNI调用耗时
2. **调用频率**：发现单帧内JNI调用次数过多
3. **数据传输**：发现大量小数据频繁传递

**解决方案：**
```c
// 优化前：频繁的小数据传递
for (int i = 0; i < imageWidth; i++) {
    for (int j = 0; j < imageHeight; j++) {
        jint pixel = get_pixel(i, j);
        // 每次处理一个像素都调用JNI
        (*env)->CallVoidMethod(env, callbackObj, callbackMethod, pixel);
    }
}

// 优化后：批量处理数据
jintArray pixelArray = (*env)->NewIntArray(env, imageWidth * imageHeight);
jint* pixels = (*env)->GetIntArrayElements(env, pixelArray, NULL);

// 在Native层完成所有像素处理
process_all_pixels(pixels, imageWidth, imageHeight);

// 一次性传递所有数据
(*env)->ReleaseIntArrayElements(env, pixelArray, pixels, 0);
(*env)->CallVoidMethod(env, callbackObj, callbackMethod, pixelArray);
```

**优化效果：**
- JNI调用次数从百万次减少到几十次
- 处理速度提升10倍以上
- CPU使用率显著降低

## 高级特性深入

### JNI引用管理
**面试问题**：JNI有哪几种引用类型？它们的生命周期是怎样的？

**回答策略：**
- **局部引用**：在当前JNI调用有效，调用结束后自动释放
- **全局引用**：跨JNI调用有效，需要手动创建和释放
- **弱全局引用**：不阻止GC，需要手动检查有效性
- **生命周期管理**：正确管理引用是避免内存泄漏的关键

### 多线程JNI
**面试问题**：在多线程环境下使用JNI需要注意什么？

**回答策略：**
- **线程关联**：JNIEnv与线程绑定，不能跨线程使用
- **全局引用**：多线程共享数据需要使用全局引用
- **同步机制**：需要实现线程同步，避免竞态条件
- **Attach/Detach**：新线程需要Attach到JVM，使用后Detach
