## 1. 系统级稳定性案例

### 1.1 小红书内存泄漏优化案例

**场景**：
- 应用崩溃率高达6.7%，严重影响用户体验
- 主要问题：内存泄漏导致OOM崩溃
- 涉及大量Activity、Fragment和资源未正确释放

**问题分析**：
```java
// 问题代码示例：静态Context引用
public class AppManager {
    private static Context sContext; // 静态Context持有Activity引用
    
    public static void init(Context context) {
        sContext = context; // Activity被静态引用，无法被GC回收
    }
}

// 问题代码示例：Handler内存泄漏
public class MainActivity extends Activity {
    private Handler mHandler = new Handler() {
        @Override
        public void handleMessage(Message msg) {
            // 隐式持有Activity引用
            updateUI();
        }
    };
    
    // 未在onDestroy中移除消息
}
```

**解决方案**：
```java
// 解决方案1：使用Application Context
public class AppManager {
    private static Context sAppContext;
    
    public static void init(Context context) {
        sAppContext = context.getApplicationContext();
    }
}

// 解决方案2：静态Handler + WeakReference
public class MainActivity extends Activity {
    private static class SafeHandler extends Handler {
        private final WeakReference<MainActivity> mActivity;
        
        public SafeHandler(MainActivity activity) {
            mActivity = new WeakReference<>(activity);
        }
        
        @Override
        public void handleMessage(Message msg) {
            MainActivity activity = mActivity.get();
            if (activity != null && !activity.isFinishing()) {
                activity.handleMessage(msg);
            }
        }
    }
    
    @Override
    protected void onDestroy() {
        super.onDestroy();
        mHandler.removeCallbacksAndMessages(null);
    }
}
```

**优化收益**：
- 崩溃率从6.7%降低到0.5%
- 内存使用量减少40%
- 用户留存率提升15%

### 1.2 腾讯团队ANR优化案例

**场景**：
- 应用频繁出现ANR（Application Not Responding）
- 主线程执行耗时操作：数据库查询、网络请求、文件读写
- 锁竞争导致线程阻塞

**问题分析**：
```java
// 问题代码：主线程执行数据库操作
public class DataManager {
    public List<User> loadUsers() {
        // 在主线程执行耗时数据库查询
        return database.query("SELECT * FROM users"); // 可能耗时数秒
    }
}

// 问题代码：同步锁竞争
public class CacheManager {
    private static final Object lock = new Object();
    private static Map<String, Object> cache = new HashMap<>();
    
    public void put(String key, Object value) {
        synchronized(lock) {
            // 耗时操作在同步块内
            processData(value); // 可能耗时
            cache.put(key, value);
        }
    }
}
```

**解决方案**：
```java
// 解决方案1：使用异步任务
public class DataManager {
    public void loadUsersAsync(Callback<List<User>> callback) {
        new AsyncTask<Void, Void, List<User>>() {
            @Override
            protected List<User> doInBackground(Void... voids) {
                return database.query("SELECT * FROM users");
            }
            
            @Override
            protected void onPostExecute(List<User> users) {
                callback.onResult(users);
            }
        }.execute();
    }
}

// 解决方案2：优化锁粒度
public class CacheManager {
    private final StripedLockMap<String, Object> cache = 
        new StripedLockMap<>(16); // 锁分段
    
    public void put(String key, Object value) {
        // 耗时操作在锁外执行
        Object processed = processData(value);
        
        // 锁内只执行快速操作
        cache.put(key, processed);
    }
}
```

**优化收益**：
- ANR率降低80%
- 应用响应速度提升3倍
- 用户满意度显著提升

### 1.3 阿里团队Native崩溃优化案例

**场景**：
- JNI层频繁出现SIGSEGV、SIGABRT崩溃
- 内存越界访问、空指针解引用
- JNI引用管理不当

**问题分析**：
```cpp
// 问题代码：内存越界访问
JNIEXPORT void JNICALL
Java_com_example_NativeClass_processArray(JNIEnv* env, jobject obj, 
                                         jintArray array) {
    jint* elements = env->GetIntArrayElements(array, NULL);
    jsize length = env->GetArrayLength(array);
    
    for (int i = 0; i <= length; i++) { // 错误：应该是 i < length
        elements[i] = process(elements[i]); // 当i==length时越界
    }
    
    env->ReleaseIntArrayElements(array, elements, 0);
}

// 问题代码：JNI引用泄漏
JNIEXPORT void JNICALL
Java_com_example_NativeClass_createGlobalRef(JNIEnv* env, jobject obj) {
    jclass clazz = env->FindClass("com/example/MyClass");
    jobject globalRef = env->NewGlobalRef(obj);
    // 忘记调用DeleteGlobalRef
}
```

**解决方案**：
```cpp
// 解决方案1：边界检查
JNIEXPORT void JNICALL
Java_com_example_NativeClass_processArray(JNIEnv* env, jobject obj, 
                                         jintArray array) {
    if (array == NULL) {
        env->ThrowNew(env->FindClass("java/lang/NullPointerException"), 
                     "array is null");
        return;
    }
    
    jint* elements = env->GetIntArrayElements(array, NULL);
    if (elements == NULL) {
        return;
    }
    
    jsize length = env->GetArrayLength(array);
    for (int i = 0; i < length; i++) {
        elements[i] = process(elements[i]);
    }
    
    env->ReleaseIntArrayElements(array, elements, 0);
}

// 解决方案2：RAII模式管理JNI引用
class ScopedGlobalRef {
private:
    JNIEnv* mEnv;
    jobject mRef;
    
public:
    ScopedGlobalRef(JNIEnv* env, jobject obj) : mEnv(env) {
        mRef = env->NewGlobalRef(obj);
    }
    
    ~ScopedGlobalRef() {
        if (mRef != NULL) {
            mEnv->DeleteGlobalRef(mRef);
        }
    }
    
    jobject get() const { return mRef; }
};
```

**优化收益**：
- Native崩溃率降低95%
- 应用稳定性显著提升
- 跨平台兼容性更好

## 2. 应用级稳定性案例

### 2.1 字节跳动内存抖动优化案例

**场景**：
- 应用出现频繁GC，导致界面卡顿
- 内存分配和释放过于频繁
- 在循环中创建大量临时对象

**问题分析**：
```java
// 问题代码：在循环中创建对象
public void processList(List<String> items) {
    for (String item : items) {
        // 每次循环都创建新的StringBuilder
        StringBuilder sb = new StringBuilder();
        sb.append("Item: ").append(item);
        String result = sb.toString();
        process(result);
    }
}

// 问题代码：频繁的Bitmap创建和回收
public void loadImages(List<String> urls) {
    for (String url : urls) {
        Bitmap bitmap = loadBitmapFromUrl(url); // 频繁创建Bitmap
        imageView.setImageBitmap(bitmap);
        // Bitmap未及时回收
    }
}
```

**解决方案**：
```java
// 解决方案1：对象池技术
public class StringBuilderPool {
    private static final int MAX_POOL_SIZE = 10;
    private static final Queue<StringBuilder> pool = 
        new LinkedList<>();
    
    public static StringBuilder acquire() {
        StringBuilder sb = pool.poll();
        if (sb == null) {
            sb = new StringBuilder();
        } else {
            sb.setLength(0); // 清空内容，复用对象
        }
        return sb;
    }
    
    public static void release(StringBuilder sb) {
        if (pool.size() < MAX_POOL_SIZE) {
            pool.offer(sb);
        }
    }
}

// 解决方案2：Bitmap缓存和复用
public class BitmapCache {
    private static final LruCache<String, Bitmap> memoryCache =
        new LruCache<String, Bitmap>(20 * 1024 * 1024) { // 20MB缓存
            @Override
            protected int sizeOf(String key, Bitmap bitmap) {
                return bitmap.getByteCount();
            }
        };
    
    public static Bitmap getBitmap(String url) {
        Bitmap bitmap = memoryCache.get(url);
        if (bitmap == null) {
            bitmap = loadBitmapFromUrl(url);
            memoryCache.put(url, bitmap);
        }
        return bitmap;
    }
}
```

**优化收益**：
- GC频率降低70%
- 界面流畅度提升50%
- 内存使用更加稳定

### 2.2 美团电量优化案例

**场景**：
- 应用耗电严重，用户投诉多
- 后台服务频繁唤醒设备
- 网络请求过于频繁

**问题分析**：
```java
// 问题代码：频繁的位置更新
public class LocationService extends Service {
    private LocationManager locationManager;
    
    @Override
    public void onCreate() {
        super.onCreate();
        locationManager = (LocationManager) getSystemService(LOCATION_SERVICE);
        
        // 过于频繁的位置更新请求
        locationManager.requestLocationUpdates(
            LocationManager.GPS_PROVIDER,
            1000, // 1秒更新一次，过于频繁
            0,
            locationListener
        );
    }
}

// 问题代码：无节制的网络请求
public class DataSyncService extends IntentService {
    @Override
    protected void onHandleIntent(Intent intent) {
        while (true) {
            // 不间断的网络请求
            syncData();
            SystemClock.sleep(5000); // 每5秒同步一次
        }
    }
}
```

**解决方案**：
```java
// 解决方案1：智能位置更新策略
public class SmartLocationService extends Service {
    private static final long MIN_TIME_MS = 30000; // 30秒最小间隔
    private static final float MIN_DISTANCE_M = 50; // 50米最小距离
    
    @Override
    public void onCreate() {
        super.onCreate();
        locationManager = (LocationManager) getSystemService(LOCATION_SERVICE);
        
        // 智能位置更新策略
        locationManager.requestLocationUpdates(
            LocationManager.GPS_PROVIDER,
            MIN_TIME_MS,
            MIN_DISTANCE_M,
            locationListener
        );
    }
}

// 解决方案2：JobScheduler智能调度
public class SmartSyncService extends JobService {
    @Override
    public boolean onStartJob(JobParameters params) {
        // 在合适的时机执行同步
        if (isCharging() && isWifiConnected()) {
            syncData();
        }
        return false;
    }
    
    public static void scheduleSync(Context context) {
        JobScheduler scheduler = 
            (JobScheduler) context.getSystemService(Context.JOB_SCHEDULER_SERVICE);
        
        JobInfo jobInfo = new JobInfo.Builder(1, 
            new ComponentName(context, SmartSyncService.class))
            .setRequiredNetworkType(JobInfo.NETWORK_TYPE_UNMETERED) // 仅在WiFi下执行
            .setRequiresCharging(true) // 仅在充电时执行
            .setPeriodic(15 * 60 * 1000) // 15分钟间隔
            .build();
        
        scheduler.schedule(jobInfo);
    }
}
```

**优化收益**：
- 电量消耗降低60%
- 后台服务资源占用减少70%
- 用户满意度显著提升

## 3. 工具使用案例

### 3.1 使用LeakCanary发现内存泄漏

**场景**：
- 应用存在隐蔽的内存泄漏问题
- 传统调试方法难以发现
- 需要自动化检测工具

**配置方法**：
```gradle
// build.gradle
dependencies {
    debugImplementation 'com.squareup.leakcanary:leakcanary-android:2.9.1'
}

// Application中初始化
public class MyApplication extends Application {
    @Override
    public void onCreate() {
        super.onCreate();
        
        if (LeakCanary.isInAnalyzerProcess(this)) {
            return;
        }
        
        LeakCanary.install(this);
    }
}
```

**检测到的典型问题**：
```java
// LeakCanary检测到的泄漏示例
// 问题：Activity被静态变量持有
public class LeakySingleton {
    private static LeakySingleton instance;
    private Context context; // 持有Activity Context
    
    public static LeakySingleton getInstance(Context context) {
        if (instance == null) {
            instance = new LeakySingleton(context);
        }
        return instance;
    }
    
    private LeakySingleton(Context context) {
        this.context = context; // 泄漏点
    }
}
```

**解决方案**：
```java
// 修复后的代码
public class SafeSingleton {
    private static SafeSingleton instance;
    private Context appContext; // 使用Application Context
    
    public static SafeSingleton getInstance(Context context) {
        if (instance == null) {
            instance = new SafeSingleton(context.getApplicationContext());
        }
        return instance;
    }
    
    private SafeSingleton(Context appContext) {
        this.appContext = appContext;
    }
}
```

**收益**：
- 自动化检测内存泄漏
- 快速定位泄漏根源
- 显著降低内存泄漏导致的崩溃

### 3.2 使用Systrace分析性能瓶颈

**场景**：
- 应用界面卡顿，但原因不明
- 需要系统级性能分析
- 定位渲染性能问题

**使用方法**：
```bash
# 录制systrace
python systrace.py --time=10 -a com.example.app -o trace.html

# 高级选项：包含更多跟踪类别
python systrace.py --time=10 \
    --categories=am,view,disk,input,gfx,webview,hal,rs,sched,freq,idle \
    -a com.example.app \
    -o trace.html
```

**分析发现的问题**：
```java
// Systrace发现的性能问题：主线程阻塞
public class MainActivity extends Activity {
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        
        // 主线程执行耗时操作
        loadHeavyData(); // 在systrace中显示为长阻塞
        
        setContentView(R.layout.activity_main);
    }
    
    private void loadHeavyData() {
        // 模拟耗时操作
        SystemClock.sleep(2000); // 2秒阻塞
    }
}
```

**优化方案**：
```java
// 优化后：异步加载数据
public class MainActivity extends Activity {
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);
        
        // 异步加载数据
        new AsyncTask<Void, Void, Void>() {
            @Override
            protected Void doInBackground(Void... voids) {
                loadHeavyData();
                return null;
            }
            
            @Override
            protected void onPostExecute(Void aVoid) {
                // 数据加载完成后更新UI
                updateUI();
            }
        }.execute();
    }
}
```

**收益**：
- 准确识别性能瓶颈
- 界面流畅度提升明显
- 用户体验显著改善

   - 完善的异常捕获和处理机制
