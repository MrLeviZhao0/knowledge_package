# 显存核心知识：异常案例与解决方法

## 1. 显存异常类型与特征

### 1.1 常见显存异常分类

#### 1.1.1 内存泄漏型异常
- **特征**：显存使用量持续增长，不随应用生命周期释放
- **表现**：应用运行时间越长，显存占用越高
- **检测方法**：监控/proc/meminfo中的显存指标变化

#### 1.1.2 内存溢出型异常
- **特征**：显存分配请求超过系统可用显存
- **表现**：分配失败，应用崩溃或黑屏
- **检测方法**：监控dumpsys SurfaceFlinger中的分配失败统计

#### 1.1.3 碎片化异常
- **特征**：显存碎片化严重，无法分配连续大块内存
- **表现**：小缓冲区分配成功，大缓冲区分配失败
- **检测方法**：分析显存分配模式和碎片率

#### 1.1.4 权限异常
- **特征**：显存访问权限不足或冲突
- **表现**：缓冲区映射失败，渲染异常
- **检测方法**：检查/proc/<pid>/maps中的权限标志

## 2. 真实异常案例库

### 2.1 案例1：SurfaceFlinger显存泄漏

#### 2.1.1 问题现象
```bash
# 系统日志显示显存持续增长
I/SurfaceFlinger(  789): Total allocated buffers: 4634496 bytes
I/SurfaceFlinger(  789): Total allocated buffers: 5634496 bytes  # 10分钟后
I/SurfaceFlinger(  789): Total allocated buffers: 6634496 bytes  # 20分钟后
```

#### 2.1.2 根本原因分析
通过分析SurfaceFlinger源码发现：
```cpp
// 问题代码：缓冲区未正确释放
status_t BufferQueueLayer::onFrameAvailable(const BufferItem& item) {
    // 缓冲区引用计数未正确管理
    mCurrentBuffer = item.mGraphicBuffer;  // 增加引用但未释放旧引用
    // ...
}
```

#### 2.1.3 解决方案
```cpp
// 修复后的代码
status_t BufferQueueLayer::onFrameAvailable(const BufferItem& item) {
    // 正确管理引用计数
    if (mCurrentBuffer != nullptr) {
        mCurrentBuffer.clear();  // 释放旧引用
    }
    mCurrentBuffer = item.mGraphicBuffer;  // 设置新引用
    // ...
}
```

### 2.2 案例2：GPU显存分配失败

#### 2.2.1 问题现象
```bash
# 应用崩溃日志
E/AndroidRuntime(12345): FATAL EXCEPTION: main
E/AndroidRuntime(12345): java.lang.OutOfMemoryError: Failed to allocate a 4194304 byte allocation with 16777216 free bytes and 13MB until OOM
E/GraphicBuffer(  789): alloc(1080, 2400, 1, 00020003, ...) failed -12 (Out of memory)
```

#### 2.2.2 根本原因分析
通过分析Gralloc分配器：
```cpp
// ION内存分配失败
int IonAllocator::allocate(...) {
    int fd = ion_alloc_fd(ionFd, size, 0, heapMask, 0);
    if (fd < 0) {
        ALOGE("ION allocation failed: %s", strerror(errno));
        return -ENOMEM;  // 返回-12错误码
    }
}
```

#### 2.2.3 解决方案
1. **优化内存使用策略**：
```cpp
// 使用更合适的内存类型
uint64_t chooseOptimalUsage(int width, int height) {
    size_t size = width * height * 4;
    if (size > LARGE_BUFFER_THRESHOLD) {
        // 大缓冲区使用CMA内存
        return GRALLOC_USAGE_HW_VIDEO_ENCODER;
    } else {
        // 小缓冲区使用系统内存
        return GRALLOC_USAGE_SW_WRITE_OFTEN;
    }
}
```

2. **实现内存回收机制**：
```cpp
class MemoryManager {
public:
    void triggerGarbageCollection() {
        if (getMemoryPressure() > PRESSURE_THRESHOLD) {
            // 强制垃圾回收
            System.gc();
            // 释放未使用的缓冲区
            releaseUnusedBuffers();
        }
    }
};
```

### 2.3 案例3：多进程显存竞争

#### 2.3.1 问题现象
```bash
# 多个应用同时运行时出现渲染异常
W/Adreno-GSL( 5678): <sharedmem_gpumem_alloc_id:2185>: sharedmem_gpumem_alloc: mmap failed errno 12 Out of memory
E/Surface ( 5678): dequeueBuffer failed (No such device)
```

#### 2.3.2 根本原因分析
- 多个应用同时申请大块显存
- GPU驱动显存资源有限
- 缺乏有效的资源调度机制

#### 2.3.3 解决方案
1. **实现显存配额管理**：
```cpp
class MemoryQuotaManager {
private:
    std::map<pid_t, size_t> mProcessQuotas;
    
public:
    bool canAllocate(pid_t pid, size_t size) {
        size_t currentUsage = getProcessMemoryUsage(pid);
        size_t quota = mProcessQuotas[pid];
        return (currentUsage + size) <= quota;
    }
    
    void setQuota(pid_t pid, size_t quota) {
        mProcessQuotas[pid] = quota;
    }
};
```

2. **优先级调度策略**：
```cpp
class MemoryScheduler {
public:
    enum Priority {
        PRIORITY_FOREGROUND = 0,
        PRIORITY_BACKGROUND = 1,
        PRIORITY_SYSTEM = 2
    };
    
    AllocationResult allocateWithPriority(Priority priority, size_t size) {
        if (priority == PRIORITY_FOREGROUND) {
            // 前台应用优先分配
            return tryAllocate(size);
        } else {
            // 后台应用可能需要等待或使用压缩内存
            return allocateCompressed(size);
        }
    }
};
```

### 2.4 案例4：显存映射权限异常

#### 2.4.1 问题现象
```bash
# 系统日志显示映射失败
E/GraphicBufferMapper( 1234): lockAsync(...) failed: Permission denied
W/System.err( 1234): java.lang.SecurityException: Requires GRAPHICS_MEMORY_PROVISIONER permission
```

#### 2.4.2 根本原因分析
- 应用缺少必要的权限
- SELinux策略限制
- 缓冲区跨进程共享权限配置错误

#### 2.4.3 解决方案
1. **权限配置修复**：
```xml
<!-- AndroidManifest.xml -->
<uses-permission android:name="android.permission.GRAPHICS_MEMORY_PROVISIONER" />
<uses-permission android:name="android.permission.ACCESS_SURFACE_FLINGER" />
```

2. **SELinux策略调整**：
```te
# SELinux策略文件
allow appdomain graphics_device:chr_file { read write open };
allow appdomain gpu_device:chr_file { read write open };
allow appdomain ion_device:chr_file { read write open };
```

public class GraphicsMemoryBestPractices {
    
    // 1. 及时释放显存引用
    public void releaseGraphicsResources() {
        if (surfaceTexture != null) {
            surfaceTexture.release();
            surfaceTexture = null;
        }
        
        if (eglSurface != null) {
            egl.eglDestroySurface(eglDisplay, eglSurface);

    // 2. 使用合适的内存格式
    public Bitmap.Config chooseOptimalBitmapConfig() {
        // 根据使用场景选择合适格式
        if (needsAlpha) {
            return Bitmap.Config.ARGB_8888;  // 4字节/像素
        } else {
            return Bitmap.Config.RGB_565;   // 2字节/像素
        }
    }
    
    // 3. 实现内存复用
    public class BitmapPool {
        private LruCache<String, Bitmap> bitmapCache;
        
        public Bitmap getBitmap(String key, int width, int height) {
            Bitmap bitmap = bitmapCache.get(key);
            if (bitmap == null || bitmap.isRecycled()) {
                bitmap = createNewBitmap(width, height);
                bitmapCache.put(key, bitmap);
            }
            return bitmap;
        }
    }
}

## 5. 应急处理流程

### 5.1 显存异常应急响应

#### 5.1.1 检测到异常时的处理
```bash
# 1. 立即收集诊断信息
adb shell dumpsys meminfo > meminfo_emergency.txt
adb shell dumpsys SurfaceFlinger > surfaceflinger_emergency.txt
adb logcat -d > logcat_emergency.txt

# 2. 尝试释放系统显存
adb shell "echo 3 > /proc/sys/vm/drop_caches"

# 3. 重启图形服务
adb shell stop surfaceflinger
adb shell start surfaceflinger

# 4. 如果问题持续，重启系统
adb reboot
```

#### 5.1.2 应用级应急处理
```java
public class EmergencyMemoryHandler {
    
    public static void handleOutOfMemory() {
        try {
            // 1. 立即释放可释放的资源
            System.gc();
            
            // 2. 清除缓存
            BitmapCache.clear();
            
            // 3. 降低图形质量
            reduceGraphicsQuality();
            
            // 4. 通知用户
            showMemoryWarningDialog();
            
        } catch (Exception e) {
            // 5. 最后手段：优雅退出
            finishActivityGracefully();
        }
    }
    
    private static void reduceGraphicsQuality() {
        // 降低分辨率
        setRenderResolution(720, 1280);
        
        // 使用低质量纹理
        setTextureQuality(LOW);
        
        // 禁用特效
        disableVisualEffects();
    }
}
```
